# Hearth v0.1.0-alpha — release notes draft

**Draft only. Do not publish or tag yet.**

## Release boundary

This build is intended for an internal Fedora appliance alpha. It improves reproducibility, diagnostics, recovery, and honest validation around the existing controller-first product. It is not claimed ready for an unattended household deployment or general release.

## Implemented

- Godot controller-first Home, Games, one-page filesystem library, Movies & TV grid, settings, System Health, and power menus.
- RetroArch, approved native PC helper, Steam Big Picture, Plex HTPC, and browser-streaming launcher boundaries.
- Editable local input/library/service settings with atomic replacement.
- Unprivileged destination-specific evdev/uinput bridge and return-to-Hearth failsafe.
- Fedora install, transactional-style update with backup, conservative uninstall, diagnostics, and user service.

## Automated and tested

- JSON/configuration/artwork/privacy/reference and documentation-link checks.
- Shell syntax, executable modes, Python compilation, and repository cleanliness.
- 28 input-bridge Python tests.
- Fedora lifecycle tests using temporary isolated roots, including preservation and privacy assertions.
- Godot headless import and menu, input, library, browser, settings, activity, and System Health smoke suites.

## Manually tested

- No new physical-appliance result is claimed by this release draft.
- Existing privacy-safe screenshots are generated from a fictional 1920×1080 fixture.

## Hardware-dependent and not yet run

All rows in [hardware validation](../hardware-validation.md), including boot/login, USB/Bluetooth/reconnect, TV scaling, audio, real Steam/Plex/RetroArch/browser launch/return, crash cleanup, suspend, and power actions.

## Experimental

- Netflix tile navigation, because external site markup changes without notice.
- Per-controller evdev matching across USB and Bluetooth identities.
- GNOME Wayland fullscreen/focus transitions across third-party applications.
- Native PC helper catalog, which is intentionally local and allowlisted.

## Known limitations

- No redistribution license has been selected; this blocks a legally clear public freeware release.
- The appliance supports Fedora as its production target; other distributions are not supported.
- Godot must be supplied to the installer; the installer does not download runtimes.
- Optional applications are reported but not silently installed.
- Hardware evidence remains incomplete.
- Fullscreen applications control their own native exit behavior when the bridge is not used.
- External streaming services require local accounts/subscriptions and can break navigation.

## Known broken or unsupported

- No specific physical controller, GPU, television, audio chain, or Bluetooth adapter is certified yet.
- Non-Fedora production deployment is rejected by the installer.
- Root execution of the input bridge and arbitrary JSON commands are deliberately unsupported.
- A persistent Wayland overlay above every third-party fullscreen application is not available by design.

## Security and privacy

No telemetry or cloud dependency was added. ROMs, BIOS files, saves, browser data, credentials, and media remain outside the repository. Diagnostics expose statuses and aggregate counts, not personal inventory. The input bridge never runs as root.

## Before publishing

1. Select and install a real project license after reviewing artwork and brand assets.
2. Run and sign the complete physical matrix on the target Fedora PC.
3. Resolve all required diagnostic failures.
4. Confirm GitHub Actions passes from a pull request.
5. Review the final diff and release notes against the tagged commit.
6. Create the tag/release only after explicit maintainer approval.
